# Методология: как искали и исправляли ошибки казахской локализации

Коротко: **сначала дешёвые точные правила, потом LLM только для того, что правила понять не могут, потом
человек**. Каждая находка объясняет себя (что не так, чем это доказано, что предлагаем), каждое изменение в
`intl_kk_fixed.arb` проверено носителем и помечено.

## 1. Поиск ошибок

### 1.1 Правила (`locqa/checks/rules.py`) — без сети, ~1 секунда на файл

| Тип | Как ловим | Пример из данных |
|---|---|---|
| untranslated | ключ есть в ru, нет в kk, или значение пустое | 12 отсутствующих ключей, 4 пустых |
| placeholder_mismatch | мультимножество `{x}`, `%s`, `<g>` в ru и kk; если пропали только скобки — восстанавливаем | `Жаңарады: time` → `Жаңарады: {time}` |
| plural_mismatch | собственный разбор ICU, обязательные формы CLDR для локали | в данных плюралов нет, поддержка покрыта тестами |
| same_as_source | совпадение с ru; предложение из ≥3 слов — high; 1–2 слова — в очередь QA (там много законных заимствований: «Профиль», «Капот») | `bankConfirmHouse` целиком по-русски |
| wrong_language | доля латиницы, маркеры узбекского (`o‘`, `-ni`, `-lar`), дословное совпадение с uz/en; бренды (слово есть в en) исключаются | `Avtorizatsiya xatosi`, португальский текст в `launcherSettingsDeleteAccountConfirm` |
| orthography | латинская буква внутри кириллического слова; слово без казахских букв встречается 1 раз, а его вариант с ә/ғ/қ/ң/ө/ұ/ү/һ/і — десятки раз | `жане` (1) против `және` (176), `бөлімiне` с латинской `i` |
| suffix_harmony | аффикс сразу после плейсхолдера по списку падежных окончаний профиля | `{price}-ге сатып алу` |
| length_overflow | короткий UI-элемент, kk ≥ 2,2× ru, ≥ 10 символов разницы и ≥ 1,8× самого длинного из en/uz | «1 день» → «1 КҮН бөліміне өту үшін басыңыз» |
| glossary_violation | запрещённый глоссарием вариант, только если в ru есть сам термин | «Баланс» → «қолма-қол ақша» («наличные») |

Языковые знания вынесены в профиль (`locqa/profiles.py`): алфавит, «похожие» буквы, аффиксы, маркеры чужих языков.
Новый язык — новый профиль, код проверок не меняется.

### 1.2 Подсказки (`locqa/checks/hints.py`) — слабые сигналы, сами в отчёт не идут

- **перевод скопирован** из другого ключа при разных ru и en (`Брак` = перевод `Законопослушность`);
- **разошлись числа** (`от 1 до 70` → `3-тен 90`);
- **кусок склеиваемой фразы** — показываем соседние ключи;
- **сквозной словарь**: как та же ru-строка переведена во всём файле. Важный урок: *большинство само бывает
  неверным* — «Отмена» → «БАСТАУ» («начать») в 5 ключах против правильного «Болдырмау» в 2. Поэтому автоматическое
  «правь по большинству» отключено: оно испортило бы правильные строки.

### 1.3 LLM (`locqa/judge.py`, промпт `prompts/judge_v3.md`)

`claude-sonnet-5.5` через OpenRouter, батчи ≤ 40 строк одного раздела игры (`@@comment`), в каждой строке — ru, kk,
en, uz, уже найденные правилами проблемы (`already_found`, их LLM не повторяет) и подсказки. Зона ответственности
LLM — только смысл, кальки, термины, настоящие опечатки. Для каждой находки модель даёт **обратный перевод** («сейчас
по-казахски написано: …») — это делает evidence понятным человеку без знания казахского. Ошибки русского исходника
модель пишет отдельно (`source_notes.json`, для студии).

Почему так, а не «один промпт на всё»: мы прогнали конвейер на имитации модели и на реальных моделях
(`docs/SIMULATION.md`). Монолитный промпт путал типы (а жюри считает recall с учётом типа) и давал 38 шумовых находок
на 588 строк; разделённый — 0 шума и точность ≈ 85–90% при том же поиске подложенных ошибок.

### 1.4 Decision-модели (`locqa/decide.py`)

OpenRouter Decisions API: типизированные вопросы, калиброванные вероятности, без свободного текста. Мы сравнили
5 моделей на размеченной выборке (`docs/SIMULATION.md`): как основной искатель они проигрывают Sonnet (тонкую
казахскую лексику не знают), но полезны как дешёвый фильтр «предпочтёт ли носитель исправление» (`nace-ai/drex-max`)
перед ревью.

## 2. Исправления

1. Механические правки делают правила (скобки плейсхолдеров, буквы ә/ғ/қ…).
2. Для остальных — `claude-opus-5.5` (`prompts/fix_v2.md`): минимальная правка, плейсхолдеры как в ru, аффиксы после
   плейсхолдера убираются перестройкой фразы («{price}-ге сатып алу» → «Сатып алу: {price}»), для фрагментов — флаг
   «нужен контекст».
3. **Автоматический шлюз** (`locqa/fix.py`): плейсхолдеры, ICU, переносы, латиница, длина кнопки, аффикс после
   плейсхолдера, запреты глоссария, комментарии в тексте правки. Не прошло — носитель видит находку без предложения.
4. **Носитель** (`locqa review`): одна карточка — ru / en / uz / сейчас / предложение / почему; принять, исправить,
   отклонить. Только одобренное попадает в `intl_kk_fixed.arb` (`locqa apply`) с метаданными
   `"x-locqa": {"reviewed_by_human": true, "reviewer", "original", "issues"}`. Файл проверяется настоящим
   `flutter gen-l10n` (`tools/l10n_check/validate.py`).

_Заполняется по итогам полного прогона и ревью._

## 5. Известные ограничения

- `gen-l10n` не принимает 3 ключа уже в исходном `intl_ru.arb` (`UNeedHelp`, `TowConfirmDesc`,
  `inventoryEquipped@description`); мы их не переименовываем — игра обращается к ним по имени.
- Пустое значение у ключей-префиксов (`*Prefix`) иногда законно: в казахском другой порядок слов, и смысл несёт
  соседний ключ. Такие строки помечены «нужен контекст».
- Точность LLM-находок — наша ручная оценка на выборке, не оценка носителя.
